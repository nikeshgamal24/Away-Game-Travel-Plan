0Code · season viewL3 Season overview
Does: gives each away game a verdict, suggested hotels and a share of the season budget
Reads: schedule.json hotels.json benchmarks.json settings.json
  • ≤ 50 mi → day trip only (example policy value)
  • > 50 mi → overnight only if a same-day trip breaks the time rules

1StaffL1 Trip request
Free text: "Sunday at Lakeview State, 1 PM kickoff. 22 players, 4 coaches, 3 staff. Train until noon Saturday. Budget $6,000."
→ or fill the form directly (skips Aivana)
A1Aivana · structured output (JSON Schema)L1 Parse request
Does: turns the text into form fields
  • game_id must be in an enum of real schedule IDs, or null
  • Missing info → null, never guessed
  • Departure day/time as a choice; code computes the date
  • Same text again → cached, no new call
→ JSON fields
2StaffL1L3 Team rules + settings
Sets: earliest departure, max game-day bus hrs, pregame meal hrs, check-in by, home by, hotel needs bus parking / meeting room
Edits: seats per bus, people per room, meal allowance, example policy values, extras
→ settings (defaults from settings.json)
3CodeL1 Validate input
Reads: schedule.json settings.json (allowed min/max)
  • Game exists · counts are whole numbers ≥ 0
  • Departure is before kickoff
  • Every setting is within its allowed range
✗ fail → error shown to staff, nothing computed
4CodeL1 Count the party
Does: travelers = players + coaches + staff · buses = ⌈travelers ÷ seats per bus⌉ · rooms = ⌈players ÷ 2⌉ + ⌈staff ÷ 1⌉
Lakeview: 29 travelers → 1 bus · 18 rooms (11 + 7)
5CodeL3 Filter hotels
Reads: hotels.json (same city as the game)
  • Game ≤ 50 mi → no hotels at all (day trip only)
  • Enough free rooms? · under the rate cap?
  • Bus parking / meeting room if the team rule requires it
  • Cost = rooms × rate × nights + tax + bus parking fee
→ usable hotels; the rest keep a reason, e.g. "H3: no bus parking (team rule)"
6CodeL1L3 Build options A–E
Reads: bus_rates.json restaurants.json flight_fares.json
  • A day trip · B lowest-rate usable hotel · C closest usable hotel
  • D flight if ≥ 400 mi and a fare exists · E 2 nights if a same-night return breaks "home by"
  • Each: timeline, bus, lodging, meals (team meal or per diem), extras, total
→ 2–5 priced options with timelines
7CodeL3 Check every option
  • Team rules: depart no earlier than · game-day travel ≤ N hrs · pregame meal N hrs before · check-in by · home by
  • Example policy values (confirm with BGSU Travel Services): overnight only > 50 mi and needed · per diem only for meals not provided · hotel ≤ $140 · flights bought 30+ days ahead
  • Budget: under / over, by how much
8CodeL1 Rank + label
Does: sorts by (rules broken + policy issues), then total cost
Labels: best within budget · best fit to rules
Lakeview: A $3,265 (breaks 2) · B $6,567.20 (keeps all) · C $7,607.20
A2Aivana · structured outputL1 Recommend + explain tradeoffs
Sees: only the computed option summaries, check results and labels
  • option_id from an enum of the real option IDs
  • Explains tradeoffs by option ID
  • Cached when the options are unchanged
→ pick + explanation
10StaffL2L3 Review options
Reads the option cards, checks and recommendation. Asks or changes things in plain words:
  • "Why is B over budget?"
  • "Leave 2 players home, coaches two to a room"
  • "Leave Saturday at 3 PM" · "Switch to Stadium Suites"
Changes so far: log + undo
9CodeL3 Fact check the AI text
Compares Aivana's text with the computed plan:
  • every $ amount · every clock time
  • every option ID · "keeps / breaks N rules" claims
Anything that doesn't match → flagged "unverified"
A3Aivana · multi-turn chat + structured outputL2 Review assistant
Sees: last 8 messages + the change log + option summaries
  • Answers questions from the computed options
  • Turns requests into edits — never computes results
  • Can never approve anything
→ answer + edits {field, op, value}
12StaffL3 Choose one option; pick hotel + meals
Full hotel and restaurant lists, with rate, bus-parking fee, meeting room, price per person. Unusable ones are greyed out with the reason.
→ custom choices (validated, then repriced)
11CodeL2L3 Apply edits + log
  • Only allowed fields; values range-checked; unknown edits rejected
  • Records each change with its effect, e.g. B $6,567.20 → $5,925.60
  • Then recomputes from step 4
13StaffL3 Approve
  • Choose an approver role (Head Coach, Dir. of Operations…)
  • Tick each broken rule, policy issue and budget overrun as accepted
  • Optional note
✓Code · hard gateL3 Approval gate
  • Every required issue ticked?
  • Server stores a SHA-256 fingerprint of request + settings + choices + option
  • Final plan, memo, .ics, actuals: 403 before approval · 409 if anything changed after
14CodeL3 Final trip plan
Reads: roster.json
  • Schedule, costs, accepted issues, approval line
  • Rooming list (injured players left out)
  • Calendar file (.ics) · expense report due date (90 days)
A4Aivana · streamingL2 Stream the trip memo
  • Only after approval; starts with the approval line
  • Uses only the approved plan's facts
  • Then fact-checked like step 9
→ memo for the team (.txt download)
15StaffL3 After the trip
Enter actual spend: transport, lodging, meals, extras. File one expense report per trip.
16CodeL3 Budget vs actual
Difference per category and against the trip budget.

Why the AI can't make up numbers

  • Aivana never does the math: it gets computed facts and sends back IDs, fields and words
  • Enums limit its game and option IDs to real ones
  • Step 9 flags any $ amount, time, ID or rule claim it can't match
  • It can't approve: only the gate can unlock the final plan

Aivana features used

  • Structured output (JSON Schema): A1, A2, A3
  • Multi-turn chat: A3
  • Streaming: A4
  • Bad JSON → retried once with the error message
  • Retries 429 / 502 / 504 honoring Retry-After · mock mode for offline demo

Token budget

  • Never sends data files or PDFs — only short summaries
  • Chat history capped at the last 8 messages
  • Same parse / recommend input → cached answer
  • Header shows calls + tokens per call type
